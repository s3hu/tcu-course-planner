# 履修ノート 社会メディア学科版

東京都市大学メディア情報学部・社会メディア学科、2025年度入学者向けの非公式履修計画補助サイトです。提供JSON v2.0.0を使い、2026年度のシラバス開講266件、科目表271件＋補助科目32件を表示します。公式サービス・卒業認定ではありません。

## 起動と検証

Node.js 22または24を使用してください。

    npm ci
    npm run dev

http://127.0.0.1:3000 を開きます。

    npm test
    npm run typecheck
    npm run build
    npm start

## データ

元ファイルは data/tcu-social-media-2025.json にそのまま保存しています。scripts/normalize.mjs は、画面で必要な項目を src/data/catalog.json に抽出します。科目IDと講義コードを保持し、科目ナンバーだけで結合しません。

    node scripts/normalize.mjs

元資料の本文をコードや指示として実行しません。シラバスの概要、目標、評価原文、前提知識、進め方、教科書等を詳細画面から確認できます。出典のPDFページ、取得日、シラバス更新日時、公式シラバスへのリンクを保持します。URLはHTTPSの大学公式ドメインに限定して表示します。

未照合の追加時間表候補229行は履修可能な開講情報に昇格させません。JSONに全件再監査済みという保証はなく、時間表訂正・個別の履修許可・クラス割当・定員は要確認です。

## 主な実装

- 対応範囲は2025年度入学・社会メディア学科。2026年度の前期／後期を切替
- 修得科目は空で開始し、0.5単位にも対応。同じ科目IDは一度だけ加算
- 外国語8、体育1、教養10、専門基礎33、専門60、自由選択12単位を区分別表示
- 各区分の最低数を超える算入可能単位を自由選択に振替。合計へは二重加算しない
- 特別講義4、教養ゼミナール4、教養特別講義6単位の科目群上限。超過分は自由選択にも算入しない
- 必修、選択必修△1・△2、DS/MS、外国語内訳、基礎体育の参考チェック
- 他学科・教職等の条件付き単位、単位数競合は卒業算入を保留。非算入科目は集計から除外
- 成績評価は原文表示。未分類の割合を試験・レポートの内訳として推定しない。レポート100%の絞り込みは src/data/reviewed-assessments.json の確認済み8開講のみを対象とする
- 全曜日（月〜土）と複数時限に対応。前期前半・後半／後期前半・後半を切替し、同じ四半期だけ重複判定
- 同一科目の別クラスは同時に仮置きできない
- 不明な個別条件は確認事項として表示し、詳細を読んで「要確認のまま仮置き」できる。履修許可の判定ではない
- 集中・活動認定等は予定一覧に表示し、通常の時間割上で安全と断定しない
- CAP参考負荷は24単位の基準を表示。個別免除や28単位への緩和は自動適用しない
- 3クラスまで比較、科目検索、JSON書出し・読込、入力消去
- 入口でゲスト／アカウントを選択し、入学年度・学部・学科を入力
- 自動時間割作成：最大8案。修得済み、同一科目、学期、前後半、曜日・時限、キャンパス、目標単位数を考慮
- 不足区分・必修優先、登校日をまとめる、朝の時間を空ける等の探索戦略。前後半のプレビューから授業詳細を確認して仮置き
- 自動作成は幅28・各分岐14の有限探索。全組み合わせの網羅・最適性は保証しない。日時不明・算入保留は自動案から除外
- 受講形式は出典で明示された情報だけを利用。元JSONにはオンデマンドの明示がないため、世田谷をオンデマンドと推定しない

## 保存モード

ゲストでは入力をメモリー内だけに保持し、localStorage・DBへ保存しません。更新・終了で消えます。既存のローカル保存キーを自動読込・削除しません。JSONバックアップは形式とデータセットIDを検証します。

アカウントではSupabase Authのメール・パスワード認証と、本人だけが読み書きできるPostgres RLSを使用します。ブラウザーには認証セッションが保存されます。プランは900msの待機後に保存し、リビジョンの一致を条件に更新します。別端末の更新を検出した場合は自動上書きを止め、JSON書出しを案内します。

### アカウントの接続手順

1. 専用Supabaseプロジェクトで supabase/migrations/202610180001_planner_accounts.sql を実行。
2. .env.example を参考に NEXT_PUBLIC_SUPABASE_URL と NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY をローカルおよびVercelに設定。公開用キーのみを使い、service_role等の管理用秘密鍵は使わない。
3. Supabase AuthのサイトURLを本番URLに、リダイレクト許可に本番URLと必要な開発URLを設定。メール確認用のSMTPを設定。
4. 再ビルド・デプロイ後、新規登録→メール確認→ログイン→作成→ログアウト→再ログインの復元、別ユーザーから読めないことを検証。

環境変数がない場合、アカウント画面は「接続準備中」と表示し、ログインや保存が動いたように表示しません。

## 保留・未対応

提供JSONの既知の問題を「データと根拠」で表示します。専門基礎はJSON採用値33単位を使いますが、資料の一部に34という記載があり、公式訂正を確認したものではありません。「未来を拓くイノベーション」は科目表1単位とシラバス2単位が競合するため、選択しても卒業算入を保留します。

在学期間・休学・進級認定、学期開始以前の前提科目修得の厳密な確認、全例外、活動・留学の個人別認定、教員免許の全要件、複数回履修の個別可否、キャンパス間移動、大学システムへの登録は自動判定しません。AI相談・成績表読取は未対応です。正式登録と卒業可否は大学の最新資料で確認してください。

## プライバシーと公開

ゲストの入力は外部へ送信しません。アカウントではメールアドレスと認証情報をSupabase Auth、基本情報・修得科目・計画を本人のDB行に保存します。氏名・学籍番号・大学のログイン情報を収集しません。フォントはGoogle Fontsから読み込み、取得できない場合は端末のフォントを使用します。

Vercelプロジェクトは既存の tcu-course-planner を更新します。検証済みソースと package-lock.json からビルドします。


## v5 — 必修確保と初回利用の見直し

今期・当該年次の未修得必修を先に確保し、過年度の必修、選択必修等の不足、区分不足、希望の順に検討します。必修と必須条件が衝突した場合は、必修を落とさず案の作成を停止します。候補ごとの必修監査で、再履修の未解決科目と理由を表示します。

検証：型検査、production build、34テスト。小規模40ケースの必修探索を全列挙と比較。ゲスト利用では保存を行いません。


## v6 — 時間から授業を選ぶ

主画面は曜日・時限別の候補表示。前半/後半を切り替え、空きコマから候補→授業詳細→全コマの仮置きへ進めます。候補数には修得・キャンパス・既存予定を反映し、他のコマで衝突する授業は追加不可の理由を表示。必修のコマへ直接移動できます。スマートフォンは曜日タブで1日ずつ表示。自動生成は折りたたみの補助機能として維持します。

検証：39テスト。時限・クォーターの正確な一致、複数コマの反映、クリックしたコマ以外での衝突、修得・必須時限条件、必修の順位を検証。


## v6.1 — 単位区分タグ

タグ定義はsrc/data/credit-tags.json、科目との対応は教育課程表と算入経路から生成します。基礎科目→外国語/体育/教養、専門基礎科目、専門科目、自由選択を区別。必修・選択必修△1/△2・DS/MSは別の条件タグです。区分未確認や算入保留を確定区分として表示しません。時間別の候補、詳細、授業一覧、計画済み授業に共通表示し、時間別候補はタグで絞り込めます。タグの階層は単位の二重加算を意味しません。既存の算入計算は変更していません。
